# AGENTS.md — lart_bms

BMS firmware for STM32F412RET6 + ADBMS6830 (Analog Devices) battery monitor ICs.

## Project structure

- `Firmware/` — STM32CubeIDE project (GNU ARM GCC 13.3.rel1)
  - `Core/Src/`, `Core/Inc/` — application code
  - `Core/Src/adbms/` — ADBMS6830 driver (Analog Devices library)
  - `Core/Src/dbc/`, `Core/Inc/dbc/` — auto-generated CAN DBC code (`powertrain_t26.dbc`)
  - `Core/Startup/` — startup assembly
  - `Debug/` — build artifacts + auto-generated makefile
  - `Drivers/` — STM32F4xx HAL + CMSIS
- `PCB/` — board images
- `Firmware/dump_to_binary/` — Python script to convert UART EEPROM dumps to `.bin`
- `Firmware/fault_manager_usage_examples.txt` — documentation only, NOT compiled

## BMS state machine (`brain.h`)

States: `BALANCING`, `CHARGING`, `IDLE`, `ONMISSION`, `STARTUP`, `DISCHARGE_TEST`, `RESET_ISA`, `FAULT`
(README is stale — it omits `DISCHARGE_TEST` and `RESET_ISA`.)

## Build

Requires `arm-none-eabi` toolchain (GNU Tools for STM32).

```bash
make -C Firmware/Debug
```

Output: `Firmware/Debug/lart_bms.elf`, `Firmware/Debug/lart_bms.bin`

## Testing

No test framework exists. This is hardware-dependent embedded firmware.

## Key conventions

- **Fault manager**: Call `RAISE_ERROR(FAULT_xxx, .field = value)` to raise, `KILL_ERROR(FAULT_xxx)` to clear. Macro uses C99 compound literals — timestamp is auto-filled. Max 63 codes (`fault_manager.h:24-96`).
- **CAN**: Two buses — CAN1 (powertrain bus), CAN2. TX uses a software queue (`can.c`). RX via registered callbacks.
- **Watchdog**: WWDG refreshed in `main.c` loop. Watchdog reset flag captured from `RCC->CSR` before peripherals init.
- **UART**: USART1 at 230400 baud (debug), USART2 at 115200. Both use DMA (`uartDMA.c`).
- **GPIO expander**: MCP23017 on I2C for 8 LEDs + DIP switch (`gpio_expander.c`).
- **Peripheral config** is generated by STM32CubeMX (`lart_bms.ioc`). Hand-edits in `main.c` go inside `USER CODE BEGIN/END` sections.
